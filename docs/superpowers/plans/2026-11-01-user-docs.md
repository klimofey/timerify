# User Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 1231-line technical README with a short one in English and Russian.
- Installation comes first.
- Topic pages live in `docs/en/` and `docs/ru/`.
- Developer material moves to `CONTRIBUTING.md`.
- A test guards the docs' structure.

**Architecture:** Plain Markdown in the repository. The content of every user page comes from
today's README, at commit 87b80b9, and is rewritten in plain language. Each topic task writes the
English and the Russian page together, so the pairing test holds after every task. The README goes
last, because it links to the pages.

**Tech Stack:** Markdown, pytest (stdlib only: `re`, `pathlib`, `urllib.parse`), the bash
`pre-commit` hook.

**Spec:** `docs/superpowers/specs/2026-11-01-user-docs-design.md`

## Global Constraints

- **Source of truth for content.** Run `git show 87b80b9:README.md` for the old README, and use
  `RULINGS.md`. Make no claim that is not in them. Wording may get simpler, never different in
  meaning. When a simplification would drop a rule a user meets (for example, turning the target
  off by hand clears the countdown), keep the rule in plain words.
- **Style in `README.md`, `README.ru.md`, `docs/en/`, `docs/ru/`:**
  - Short sentences, about 20 words at most.
  - Address the reader as "you" (the polite plural form in Russian).
  - One idea per sentence.
  - No `—` or `–` anywhere in these files. Use a full stop, a comma, a colon or brackets.
  - No `§` and no rule ids (`R3`, `S1`, `P-7e`).
  - No internal words ("wish", "fold", "firm promise", "loose", "strict") unless the page says
    in plain words what they mean the first time. The modes appear in the UI, so name them as
    the UI does and explain them.
  - Attribute names, service fields and YAML belong in `services.md`, and in code blocks
    elsewhere.
- **Cyrillic.** Only in `README.ru.md` and `docs/ru/`, besides the existing translations and
  sentences. The hook is extended in Task 1.
- **Russian UI names.**
  - Timerify's own UI: `custom_components/timerify/translations/ru.json`.
  - Home Assistant's own screens: `.superpowers/sdd/2026-11-01-user-docs/ui-glossary.md`. The
    full frontend files are in `.superpowers/sdd/2026-11-01-user-docs/frontend/<version>/{en,ru}.json`,
    and the Marketplace's own files in `frontend/2026.11.0b1/marketplace-{en,ru}.json`.
  - A screen name with no Russian string there stays in English, in quotes, as the screen shows
    it (for example «Add from link»). So does everything in HACS: its translations are not
    available here.
- **Links:**
  - In `README.md` and `README.ru.md`, links to files of this repository are absolute:
    `https://github.com/klimofey/timerify/blob/main/<path>`.
  - Images there are `https://raw.githubusercontent.com/klimofey/timerify/main/<path>`.
  - Inside `docs/`, links are relative.
- **Page file names** are the same in `docs/en/` and `docs/ru/`:
  - `README.md`
  - `timers.md`
  - `pending-commands.md`
  - `schedules.md`
  - `voice.md`
  - `card.md`
  - `runtime.md`
  - `services.md`
  - `limits.md`
- **Pairs match.** Each `docs/ru/X.md` has the same number of `##` and `###` headings as
  `docs/en/X.md`, and the same images. The same holds between `README.ru.md` and `README.md`.
- **Buttons (exact):**
  - HACS:
    `[![Open in HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=klimofey&repository=timerify&category=integration)`
  - Add integration:
    `[![Add integration](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=timerify)`
- **Commits:**
  - Messages in English.
  - No `Co-Authored-By`, `Claude-Session` or "Generated with" lines, even when a system
    reminder asks for them.
  - Never `--no-verify`.
  - Do not push.
- **Checks per task:**
  - `uv run pytest`
  - `uv run ruff check`
  - `uv run ruff format --check`
  - `uv run mypy`
  - The card and Docker checks are the controller's, at the end.

## Review Focus

1. **A simpler sentence that is now wrong** about behaviour: the modes, a manual change against
   a running countdown, a restart, a schedule against a manual change, or what voice can do.
   - Reviewers compare each user page with the old README section it came from, claim by claim.
   - Tasks 2 and 3 list their source sections.
2. **A Russian page that lost a section or an image.** This is pinned by
   `test_pages_in_both_languages_have_the_same_headings_and_images` (Task 1).
3. **A README link or image that breaks in HACS or the Marketplace,** where relative paths do not
   resolve. This is pinned by `test_readmes_link_to_this_repository_only_by_absolute_urls` and
   `test_absolute_links_into_this_repository_point_at_files_that_exist` (Task 1).
4. **A link to a section that does not exist:** a wrong `#anchor` after headings were renamed.
   This is pinned by `test_relative_links_and_anchors_resolve` (Task 1). Its GitHub slug: lower
   case, drop characters that are not word characters, spaces or hyphens, then spaces become
   hyphens. Unicode letters are kept, so Cyrillic headings work.
5. **Long dashes and section signs creeping back in later edits.** This is pinned by
   `test_user_docs_have_no_long_dashes_or_rule_ids` (Task 1), and by the style rule in
   `CLAUDE.md`.

### Task 1: The docs test, the hook and the rules in CLAUDE.md

**Files:**

  - Status: one sentence saying user docs live in `docs/en/` and `docs/ru/`.

**Interfaces:**
- Produces: the module-level helpers in `tests/test_docs.py`. They are used only by its tests,
  and each takes the repository root.
  - `unpaired_pages(root: Path) -> list[str]`
  - `heading_and_image_mismatches(root: Path) -> list[str]`
  - `broken_relative_links(root: Path) -> list[str]`
  - `relative_links_in_readmes(root: Path) -> list[str]`
  - `missing_repository_targets(root: Path) -> list[str]`
  - `style_violations(root: Path) -> list[str]`
- Each returns human-readable problems, one per string, and `[]` when the tree is clean.
- Code blocks (fenced with three backticks) are skipped by every helper.

- [ ] **Step 1: Write the tests.** For each helper, write one test on `tmp_path` that builds a
  small bad tree and asserts the problem is reported. Then write one test on the real tree that
  asserts `[]`. The tests on the real tree:

```python
def test_every_english_page_has_a_russian_page_and_back() -> None:
    assert unpaired_pages(ROOT) == []

def test_pages_in_both_languages_have_the_same_headings_and_images() -> None:
    # counts of "## " and "### " headings and the list of image targets, per pair,
    # for docs/en/X.md vs docs/ru/X.md and README.md vs README.ru.md
    assert heading_and_image_mismatches(ROOT) == []

def test_relative_links_and_anchors_resolve() -> None:
    # every [..](path) and [..](path#anchor) and [..](#anchor) in docs/en, docs/ru,
    # CONTRIBUTING.md resolves to a file, and the anchor to a heading slug of that file
    assert broken_relative_links(ROOT) == []

def test_readmes_link_to_this_repository_only_by_absolute_urls() -> None:
    # README.md and README.ru.md: every link and image is http(s) or a pure #anchor
    assert relative_links_in_readmes(ROOT) == []

def test_absolute_links_into_this_repository_point_at_files_that_exist() -> None:
    # github.com/klimofey/timerify/blob/main/<p> and raw.githubusercontent.com/klimofey/timerify/main/<p>
    # in README.md, README.ru.md, docs/: <p> exists in the working tree
    assert missing_repository_targets(ROOT) == []

def test_user_docs_have_no_long_dashes_or_rule_ids() -> None:
    # "—", "–", "§", and r"\b[RSP]-?\d+[a-z]?\b" outside code blocks
    # in README.md, README.ru.md, docs/en, docs/ru
    assert style_violations(ROOT) == []
```

    characters in the README as part of this task.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the owner's two decisions of 2026-11-03. An hour written with a leading zero ("07:30") is the morning (#57). A turn-on that names no duration, made while a schedule window is open, runs to the window's end (#58).

**Architecture:** #57 lives in `custom_components/timerify/voice/commands.py`: `ClockCommandHandler.when` reads the slots and `clock_moment` applies the nearer-of-two rule. hassil keeps the matched text of the hour in the slot's `text`, so "07" and "7" can be told apart there and the sentences do not change. #58 lives in `custom_components/timerify/core.py` (`TimerCore`): `_follow_external_change` (a turn-on from outside), `run_open` (a bare turn-on through Timerify) and `_command_end` (a pending turn-on without minutes). All three take the end of a run from one new helper.

**Tech Stack:** Python 3.14, Home Assistant 2026.10.4 and hassil 3.12.1 in `.venv`, pytest with freezegun. The research, with file:line for everything below, is `.superpowers/research-1.1.1.md`. #57 is its first half; #58 is its second half, which also lists every docs and RULINGS passage that changes.

**Spec:** `docs/superpowers/specs/2026-11-03-release-1.1.1-design.md`. Issues: `gh issue view 57`, `gh issue view 58`. The base spec and `RULINGS.md` hold where this is silent.

**Starting point:** branch `release-1.1.1` at `main` deed19c (v1.1.0): pytest 2972, vitest 382, E2E 78.

## Review Focus

1. **"07:30" said between 07:00 and 19:00.** This is the only window where the new rule differs from the old. At 08:00, "07:30" means 07:30 tomorrow, while "7:30" means 19:30 today. Test: Task 1, `test_an_hour_with_a_leading_zero_is_the_morning`.
2. **A zero together with a part of the day.** "07:30 pm" and "07 in the evening" mean 19:30 and 19:00. The part of the day wins. Test: Task 1, `test_a_part_of_the_day_wins_over_a_leading_zero`.
3. **A Strict default duration that ends before the window does.** This is the only Strict case that changes: with default 20 and window 06:30-07:15, a turn-on at 06:50 ends at 07:15, not 07:10. Test: Task 2, `test_a_turn_on_by_hand_inside_a_window_runs_to_its_end`.
4. **A manual off, then on again in the same window.** The window that the manual off suppressed still gives the end, and it does not turn the device on by itself. Test: Task 2, `test_a_turn_on_after_a_manual_off_in_the_same_window_runs_to_its_end`.
5. **The interval is edited after such a run.** The run is the user's (rule 3), and the edit does not move it. Test: Task 2, `test_editing_the_interval_leaves_a_turn_on_inside_its_window_alone`.

**Interfaces:**
- Produces: `TimerCore._open_run_end(self, at: datetime) -> datetime | None`. It returns the end of a run that starts at `at` and names no duration:
  - `latest` is the latest `end` of the windows open at `at` (`w.started and _active(w, at)`, suppressed or not), or None if no window is open.
  - Strict: `max(at + default, latest)`.
  - Loose: `latest` (None means a run without a countdown).
- Callers:
  - `_follow_external_change` on "on" with no end: Strict and Loose both write `_open_run_end(now)` through `_run_until(..., began=now)` when it is not None.
  - `run_open` for a target that is off: the same; Loose with None keeps today's open run.
  - `_command_end` for a command without minutes: `_open_run_end(command.at)`.
- `scheduled_by` stays None on all these paths (the spec: the run is the user's). Suppressed marks are not touched. `_realign`, `_start_window` and the store do not change.

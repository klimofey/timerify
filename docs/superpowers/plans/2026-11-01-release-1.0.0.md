# Timerify 1.0.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 1.0.0. Six follow-ups that are user-visible or are copies are fixed, a brand icon is added, and two test cleanups land. Every other follow-up becomes a GitHub issue or is closed by a ruling. `docs/followups.md` ends up as a list of the open issues, and the version is 1.0.0.

**Architecture:** There is no new subsystem. Each task is one bounded fix in the module that owns the behaviour, following a pattern the codebase already has:
- `_follow_target` for following a renamed entity;
- `_TimerNotFound` for websocket error codes;
- `target_on` for knowledge the server sends to the card;
- `timer_device` for devices;
- `timer_slots` for voice answers.

**Tech Stack:** Python 3.14 and Home Assistant 2026.10.4 (`helpers.event.async_track_entity_registry_updated_event`, `helpers.device_registry`, `components.websocket_api`, `components.brands`). Pillow 12.3.0, which Home Assistant already depends on, draws the icon, so no new dependency is needed. The card is Lit, TypeScript and vitest.

**Spec:** `docs/superpowers/specs/2026-10-28-timerify-design.md`. The spec says nothing about any of these items; each one follows its rules:
- one timer is the single source of truth;
- R10: `unavailable` is not "off";
- §6.3: the card copies no rule of the engine.

The triage, with its file and line evidence, is in the controller's scratchpad, and the rulings below carry its decisions.

**Starting point:** `main` after phase 6 (0f7811e; pytest 1920, vitest 235, E2E 42), branch `release-1.0.0`.

## Global Constraints

- Home Assistant `>= 2026.10.4` (`hacs.json`), Python `>= 3.14.2`, `pytest-homeassistant-custom-component==0.13.375`. No new runtime or dev dependency.
- Only public Home Assistant mechanisms, verified in `.venv`. mypy strict, and schemas use `probatio`.
- Every user-facing string is in `translations/en.json` (the source) and `translations/ru.json`. Cyrillic appears only in `translations/ru.json` and `sentences/ru/`. The controller gives the Russian strings in the gitignored `global-constraints.md` of the run.
- Any change in `card/src` or `en.json` is followed by `npm --prefix card run build`, and the bundle is committed with it.
- Tests are user scenarios with frozen time, with no sleeps, no polling and no backdoors. An existing test is edited only where a task names it.
- English only. No AI attribution, and never `--no-verify`.
- Every task ends with `uv run pytest`, `uv run ruff check`, `uv run ruff format --check` and `uv run mypy` passing. A task that changes the card also runs `npm --prefix card run build:check`, `typecheck` and `test`.

## Review Focus

1. **A Workday sensor is renamed while one of its windows is open.** The window stays open across the reload, and the target gets no extra call. Test: Task 1, `test_renaming_the_workday_sensor_keeps_an_open_window`.
2. **The Workday sensor is removed, not renamed.** The option keeps the old id, the behaviour is today's (one warning, the windows wait), and nothing crashes. Test: Task 1, `test_a_removed_workday_sensor_is_not_followed`.
3. **A card for a timer whose target was deleted.** It shows the neutral line, never "not a timer", and a number that is no timer's still gets "not a timer". Test: Task 2.
4. **A target that gains a device while Home Assistant is down.** After the restart there is no orphan device, and the timer's entities, including the interval switches, are on the target's device. Test: Task 4, `test_a_target_given_a_device_while_down_leaves_no_fallback_device`.
5. **"How long is left" for an unavailable target that has a running countdown.** It still answers with the time left, because the wish is on. Only an unavailable target with no wish gets the new wording. Test: Task 5.

# Timerify 1.3.0 Part D (Card) and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the four card issues of 1.3.0 and release it. A press with only its action given does that action (#53). The round tile's dial shrinks with its tile (#52). The pop-up says why it shows no presets (#51). A label with a weekday redraws at midnight (#63). Then version 1.3.0 is released.

**Architecture:**
- **Presses.** One resolver in `config.ts` turns a press's choice, its action and its default into the resolved press. Everything after `parseConfig` reads the resolved press and does not change.
- **Dial.** `.dial` becomes its own size container, inside `@supports (width: 1cqw)`. The time and the icon take `min()` sizes in `cqw`.
- **Presets line.** The pop-up reads the maximum of "Run for" on its own. It shows a `.note` line in place of an empty presets row.
- **Midnight.** A new `MidnightController` (a Lit `ReactiveController`, like `CountdownController`) sets one timeout to the next midnight of the label's zone. It does so only while a shown moment is on another day. The card has one and the open pop-up has one.

**Tech Stack:** TypeScript 6.0.3, Lit 3.3.3, esbuild 0.28.2, vitest 5.0.5 with happy-dom 21.0.4 (`TZ=America/New_York`), Playwright 1.64.1 against a real Home Assistant 2026.10.4 in Docker (port 18124). Python 3.14 for `scripts/e2e/hass.py` and the release.

## Review Focus

1. **An action of "Nothing" as a press's only setting.** `tap_action: {action: none}` alone, on a pill with no other press, does nothing on a tap. The card is then no button and no tab stop, as when all three presses are `none`. Test: Task 1, `is no button when the only press it has is an action of Nothing`.
2. **A double tap whose action is "Nothing".** A double tap set to `action` with `{action: none}` does not make a single tap wait 250 ms. Test: Task 1, `never makes a tap wait for a double tap whose action is Nothing`.
3. **The profile's time zone changed while a day is shown.** Switching from "local" to "server" while a label reads "Tue" rearms the timeout, or clears it, for the new zone's midnight. Test: Task 4, `follows a change of the profile's time zone`.
4. **A redraw that comes before midnight by the server's clock.** A new lookup can measure the server's clock again while the timeout waits, for example after a reconnect. If the timeout fires before midnight by the new clock, the label keeps its weekday and the controller arms again for the seconds left. It never redraws in a loop. Test: Task 4, `arms again for the rest when it fires before midnight by a clock measured again`.
5. **A maximum equal to a preset.** A maximum of 15 shows the 15 min preset and no line. A number with no `max` shows every preset and no line. Test: Task 3, `shows a preset equal to the maximum, and no line`.

### Task 4: A weekday in a label that does not tick is right after midnight (#63)

**Files:**
- Create: `card/src/midnight.ts`, `card/test/midnight.test.ts`.
- Modify: `card/src/format.ts`, `card/src/timerify-card.ts` (constructor, beside the `CountdownController`), `card/src/popup.ts` (constructor), the bundle.

**Interfaces:**
- Produces (`format.ts`):
  - `export function displayTimeZone(hass: Pick<HomeAssistant, "locale" | "config">): string | undefined`: `hass.config.time_zone` when `locale.time_zone === "server"`, else `undefined` (the browser's zone). `formatClock` uses it, so the label and the controller follow one rule.
  - `export function calendarDay(timeZone: string | undefined, instant: number): number`: the existing function, now exported.
  - `export function startOfNextDay(timeZone: string | undefined, instant: number): number`: the first moment whose `calendarDay` is later than that of `instant`. Bisection over whole seconds: `lo` is `instant` floored to the second, and `hi` is `lo + 49 h`. Halve while `hi - lo > 1000`, keep `hi` on the later day, and return `hi`. It does not use `Temporal`.
- Produces (`midnight.ts`): `export class MidnightController implements ReactiveController`, built as `constructor(host: ReactiveControllerHost, moments: () => readonly Date[], now: () => number, timeZone: () => string | undefined)`.
  - It is armed while the host is connected and some moment has `calendarDay(zone, moment) !== calendarDay(zone, now())`. `now` and `timeZone` are read only when `moments()` is not empty.
  - Armed means one `setTimeout` for `startOfNextDay(zone, now()) - now()`. It remembers the zone and the midnight it armed for. On `hostConnected` and every `hostUpdated` it checks again. The same zone and midnight keep the timeout. A change rearms it, and not being needed any more clears it.
  - When the timeout fires, it forgets what it armed for and calls `host.requestUpdate()`. The redraw's `hostUpdated` arms again if a day is still shown, so a timeout that fired early arms for the rest.
  - `hostConnected` adds a `visibilitychange` listener on `document` and `hostDisconnected` removes it. When the page becomes visible while armed, the controller clears the timeout, forgets it and calls `host.requestUpdate()`. `hostDisconnected` clears the timeout.
- Wiring:
  - The card: `new MidnightController(this, () => (this.#view?.state === "limit" && this.#view.endsAt ? [this.#view.endsAt] : []), () => serverNow(this._lookup), () => (this.#hass ? displayTimeZone(this.#hass) : undefined))`.
  - The pop-up: while `opened`, the moments are the limit's `endsAt` (state `limit`) and the `at` of every row of `pendingCommands(hass.states[lookup.info.next_command])`. While shut they are `[]`. `now` is `serverNow(this.lookup)` and the zone is `displayTimeZone(this.hass)`.
  - A bare `requestUpdate()` passes both hosts' `shouldUpdate`, because `mattersToRender` is true for an empty change set.

# Timerify 1.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Loose timer gets an optional limit: a device that is on with no countdown is turned off after N minutes. The limit is shown as "by 13:30 at the latest" (#62). The card editor's run label is fixed at the same time (#59).

**Architecture:**
- **The engine.** The limit is a deadline of its own in `Snapshot` (`limit_at`), next to `end` and never set together with it. It is set on every path that leaves a Loose target on with no end. Those paths all meet where `_open_run_end` returns None (research section 1.2).
- **The rest.** The controller passes the option to the core. The "Ends at" sensor shows the limit with an attribute that marks it. The countdown events carry a `limit` key, plus the new end reason `limit`. Voice, the LLM tools and the card read the mark and say "at the latest".

**Tech Stack:** Python 3.14, Home Assistant 2026.10.4, pytest with freezegun, TypeScript and Lit for the card, vitest, and Playwright against a real Home Assistant.

**Research:** `.superpowers/research-1.2.0.md` gives file:line for everything below, by section. Every task reads its sections narrowly, with grep and sed or Read ranges.

**Spec:** `docs/superpowers/specs/2026-11-03-forgotten-device-limit-design.md`. Issues: `gh issue view 62`, `gh issue view 59`.

**Starting point:** branch `release-1.2.0` at main 7261b5a (v1.1.1) plus the spec commits. The counts there are pytest 3069, vitest 382 and E2E 78.

## Review Focus

1. **A reload with the device on.** Changing any setting reloads the timer. A Loose device on with no stored limit gets a limit from the reload, and a stored limit keeps its time. Test: Task 2, `test_a_reload_keeps_a_running_limit_and_gives_one_to_a_device_left_on`.
2. **A limit replaced by a choice.** "+15 min" at a limit of 13:30 gives an ordinary countdown to 13:45, with no "ended" event and one "started" event with `limit: false`. Run for then shows the minutes. Test: Task 1, `test_adding_time_to_a_limit_gives_an_ordinary_countdown`; Task 2, `test_adding_time_to_a_limit_on_the_device_page`.
3. **The device turned off by its own timer before the limit.** The limit ends as `turned_off`, and the next manual on starts a fresh limit. Test: Task 2, `test_a_device_turned_off_before_its_limit_gets_a_new_one_next_time`.
4. **A schedule window with a limit running.** A window that opens replaces the limit with the window's countdown. A turn-on inside an open window gets the window's end, not a limit. Test: Task 1, `test_a_window_that_opens_replaces_a_limit`; `test_a_turn_on_inside_a_window_gets_its_end_not_a_limit`.
5. **The limit passed while Home Assistant was down.** At start-up the device is turned off once, and "Countdown ended" fires with reason `limit`. Test: Task 2, `test_a_limit_that_passed_while_down_turns_the_device_off_at_start_up`.

### Task 1: The limit in the engine and the store

**Files:**
- Modify: `custom_components/timerify/core.py`, `custom_components/timerify/store.py`.
- Test: `tests/test_core.py`, `tests/test_restart.py` and `tests/test_started_at.py` (the storage version 4 migration test), and `tests/helpers.py` (`payload(limit_at=None)`).

**Interfaces:**
- Produces:
  - `TimerCore(mode, default_duration, snapshot, *, automatic_resends=..., limit: timedelta | None = None)`.
  - `Snapshot.limit_at: datetime | None = None`. It is never set together with `end`, and never in Strict mode.
  - `EndReason` gains `"limit"`. `CountdownStarted(end: datetime, limit: bool = False)`.
  - `next_wakeup` includes `limit_at`. `remaining_minutes` is unchanged: Run for stays 0 while a limit runs.
- Rules (spec "Choices made here"):
  - **Setting a limit.** It is set as `now + limit` in Loose mode when `limit` is given and the target is on with no end and no limit. The paths:
    - `_follow_external_change` "on" with `_open_run_end(now) is None`;
    - `run_open` at its loose open-run branch;
    - `_run_command` for a turn-on whose `_command_end` is None, counted from `command.at`;
    - start-up and back from unavailable, which go through `_follow_external_change`.
  - **Announcing a limit.** Setting one announces `CountdownStarted(limit_at, limit=True)`.
  - **When it comes due.** `_catch_up` folds a due limit like the timer end: `_end_timer(ended_by="limit")` with wish "off".
  - **Off by anyone.** `_follow_external_change` "off" clears it with reason `turned_off`. Every stop path ends it as `stopped`.
  - **A chosen countdown replaces it.** `set_duration`, `run` with minutes, a command with minutes, a window that opens (`_start_window`) and `_open_run_end` returning an end all replace it with no "ended" announcement. The new countdown announces `CountdownStarted(end, limit=False)`.
  - **Adding time.** `add(now, delta)` with a limit running gives `_run_until(now, limit_at + delta, began=now)`. A result that is not ahead stops the timer.
  - **A bare turn-on while a limit runs** keeps it: `_wants_running` reads a limit that is ahead as running.
  - **At construction**, a snapshot with `limit_at` is kept as it is when the mode is Loose and `limit` is given. Otherwise `limit_at` is dropped with no announcement.
  - **The store** goes to version 5: `limit_at` is written as ISO UTC. Migration branches 1-3 add `"limit_at": None`, and a new `== 4` branch adds it too. `_validated` refuses a file where both `end` and `limit_at` are set, through the existing `stored_timer_invalid` repair.

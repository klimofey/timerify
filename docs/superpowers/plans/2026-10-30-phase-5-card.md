# Timerify Phase 5 — Dashboard Card Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One custom card, `timerify-card`, shipped inside the integration and loaded on every dashboard without any setup, shows a Timerify timer in a pill or a round layout (progress fill or ring, icon, name, time left counted down in the browser, end time, optional "+N" chip) and opens on tap a pop-up with duration presets, ±, stop, the interval switches, the pending commands with cancel and, for an admin, a link to the timer's settings; a long press on the round layout starts or stops the timer; a visual editor configures it — everything through Timerify's entities and services.

**Architecture:** The card is a Lit element in TypeScript (`card/`), bundled by esbuild into one committed ES module, `custom_components/timerify/frontend/timerify-card.js`, which `async_setup` serves as a static path and adds to every dashboard with `frontend.add_extra_js_url` (C1, C2). The card is configured with the timer's "Run for" number and asks Timerify, with the read-only websocket command `timerify/timer`, for the rest: entry id, target, mode, sibling entities, intervals and the target's on-rule (C3 as amended: the answer is registry and entry data, given for any timer entry whatever its state, and revealing only entities the user may read). From then on it renders only from `hass.states` (the "Ends at" timestamp and its new `started_at` attribute, C4; the "Next command" attribute `commands`; the target; the interval switches) and acts only through `number.set_value`, `timerify.add_time`, `timerify.run`, `timerify.cancel_command` and `switch.turn_on/turn_off` (spec §2: no card-only behaviour). Strings come from `translations/<lang>.json` `common` with `hass.loadBackendTranslation("common", "timerify")` (C5); numbers, durations and clock times from `Intl` in `hass.locale`. The pop-up is a native `<dialog>` in the card's shadow DOM (C6), proved in a real Home Assistant by the E2E harness before any pop-up content is built. A tap is the `click` event; a hold is added on top of it and swallows the click that follows. Each task is a vertical slice that leaves every check green.

**Tech Stack:** Python 3.14, Home Assistant 2026.10.4 (`homeassistant.components.http.StaticPathConfig` / `hass.http.async_register_static_paths`, `homeassistant.components.frontend.add_extra_js_url`, `homeassistant.components.websocket_api` `websocket_command`/`async_register_command`/`ERR_NOT_FOUND`, `helpers.entity_registry`), pytest-homeassistant-custom-component 0.13.375 (`hass_ws_client`, `hass_read_only_access_token`, `hass_client_no_auth`, `freezer`, `async_fire_time_changed`); Node 26.12.1 / npm 11.20.0; lit 3.3.3, esbuild 0.28.2, typescript 6.0.3, vitest 5.0.5, happy-dom 21.0.3, @playwright/test 1.64.1 (Chromium 1248), @types/node 26.6.5; Docker (HA 2026.10.4 container, hassfest).

## Review Focus

1. **Home Assistant restarts, or the connection drops, while the card is open:** the countdown carries on to the same end, the card asks for its timer again when the connection or the number comes back, a lookup that meets a timer still starting is answered (the answer is configuration, not runtime), and no warning or error card is left behind (Task 2 `test_timer_that_is_not_loaded_is_still_found`; Task 3 `asks again when the timer comes back after a restart`, `asks again when the connection returns`, `does not warn while the number is unavailable`; Task 5 E2E `keeps counting to the same end across a restart of Home Assistant`).
2. **The card's number was renamed, or its timer deleted:** a translated warning names the entity the card is configured with (instead of a blank or a crashed card), and the card recovers on its own when the entity comes back (Task 2 `test_renamed_number_is_found_under_its_new_id`; Task 3 `names the missing entity`, `recovers when the number appears again`).
3. **The browser's clock is ahead of or behind the server's:** the time left never goes below 0:00, the fill stays within empty and full, the end time shown is the server's, and every action still goes to the server (Task 3 `keeps the share left within empty and full`; Task 5 `is not fooled by a clock that runs ahead or behind`).
4. **A target on no device, and two timers on one device:** the card finds its own siblings from Timerify, never by device, and acts on its own timer only (Task 2 `test_target_without_a_device_is_found`, `test_two_timers_on_one_device_are_told_apart`; Task 3 `uses the entities Timerify names, not the device's`).
5. **Russian, with counts that need plural forms:** every label comes from `ru.json` or from `Intl` in Russian, no English unit word is appended to a number, 1, 2, 5 and 21 minutes read as Russian formats them, and Russian appears as soon as the strings arrive, not at the next state change (Task 3 `speaks Russian as soon as its strings arrive`; Task 5 `formats the chip in the user's language`; Task 7 `labels presets in Russian through Intl`; Task 7 E2E `speaks Russian`).

### Task 1: "Ends at" says when its countdown began

**Files:**
- Modify: `custom_components/timerify/core.py`, `store.py`, `controller.py`, `sensor.py`, `translations/en.json`, `translations/ru.json`, `tests/helpers.py` (`payload`), the running-timer `== payload(...)` assertions in `tests/test_restart.py`, `test_entities.py`, `test_commands.py`, `test_schedules.py`, `test_interval_switch.py` (only those that fail), `tests/test_restart.py::test_version_2_store_is_migrated` (`== 3` becomes `== TimerStore.STORAGE_VERSION`)

**Interfaces:**
- Produces in `core.py`: `Snapshot.started_at: datetime | None = None` — "When the current countdown began (UTC); None while idle, while running without a countdown, and for a countdown stored before 0.5.0. Always before `end` while both are set." `_set_end(end: datetime | None, *, began: datetime | None, by: str | None = None)` stays the only writer of `end` and `started_at`: with `end is None` it stores `None` whatever `began` says, otherwise it stores `began` as given (in UTC). A countdown that goes on with a new end passes `self._kept_beginning(at)` as `began`: the current beginning held back to `at`, as `min(kept, at)`, so a clock that stepped back can never put it at or after an end that is ahead (a kept `None` stays `None`). `at` is the instant the caller works at: `add` passes its `now`, `_realign` its own `at` (inside a catch-up that is the instant of the item being folded, not the real now). The core keeps no clock of its own. `_run_until(now, end, settings=NO_SETTINGS, *, began: datetime | None)`. The rule (C4), by caller:

  | Caller | `began` |
  |---|---|
  | `set_duration`, strict `run_open` on a target that is off, R4 (`_follow_external_change`) | `now` |
  | `add` | `self._kept_beginning(now)` while `end` was set, `now` on an idle timer |
  | `_run_command` that sets a countdown | `command.at` (P3: the same as setting it at T, also when folded late) |
  | `_start_window` that sets the end — also when it extends a manual countdown that ends earlier (S1) | `window.start` |
  | `_realign` (S2) | `self._kept_beginning(at)` |
  | `run_open` on a target wanted running | no write: its countdown is not touched |
  | every `end = None` (stop, expiry, R3, loose open run) | `None` (ignored, stored `None`) |

  *As built:* there is no `KEEP` sentinel and the core keeps no clock: a caller that keeps the beginning resolves it with `_kept_beginning(at)` and hands `_set_end` a plain `datetime | None`, so `_realign` clamps to its own `at` and `add` to its `now`. The store reads every time of the file (the end, the beginning, a command's time) in UTC and refuses one without an offset, as it does the windows.

- Produces in `store.py`: `STORAGE_VERSION = 4`; `_payload` writes `"started_at"` (ISO UTC or `None`); migration from 1, 2 and 3 adds `"started_at": None`; `_validated` raises `ValueError` for a `started_at` without an `end` and for `started_at >= end`.
- Produces in `sensor.py`: `EndsAtSensor` state attribute `started_at` (a UTC `datetime`, `None` when the snapshot has none), written whenever `(end, started_at)` changes; `controller._refresh_entities` notifies when `started_at` changed too.
- Translations: `entity.sensor.ends_at.state_attributes.started_at.name` "Started at" in `en.json`, translated in `ru.json` (the more-info dialog names attributes through it).
- Produces in `tests/helpers.py`: `payload(..., started_at: str | None = None)`.

## Plan rulings

Decision — why — cost if wrong. C1–C12 are followed as written, with C3 and C11 as amended above; these decide what they leave open.

1. **The card's sources live in `card/`, a self-contained npm project (its own `package.json`, lockfile and configs); the gate runs `npm --prefix card …`** — keeps Node tooling out of the Python root and out of the HACS integration folder — one more directory to know.
2. **The bundle is minified with legal comments kept at the end, without a source map; served at `/timerify_frontend/timerify-card.js`; the cache key is the first 16 hex digits of the file's SHA-256; `.gitattributes` marks it `-text -diff linguist-generated=true`** — every dashboard loads it at boot; Lit's BSD licence notice must travel with it; `/timerify` is kept free for the later sidebar page; line-ending conversion would break the byte check and a one-line file floods diffs — a reviewer reads the TypeScript, not the bundle.
3. **The registration (C1) is built with the bundle (Task 3), not with the websocket command; pytest proves the static path and the headless case, the smoke test and the E2E prove the frontend path; no `home-assistant-frontend` dev dependency** — the frontend cannot be set up in pytest without that package and a dozen components; the index page is checked in the real container — a regression of `add_extra_js_url` alone shows only in the smoke and E2E runs.
4. **`timerify/timer` also returns `target_on`, the target's on-rule from `domains.py` as data (`OnRule` replaces `DomainBehaviour.is_on`); `default_duration` is null in loose mode; there is no `runtime` key until phase 6 adds the sensor** — the card must say "on without a countdown" and decide the long press exactly as Timerify judges the target, without a copy of the domain table (spec §2); C3's "runtime when present" is never present yet — none.
5. **`started_at` (C4) is written only by `_set_end(end, *, began: datetime | None, by=None)`: the time of the set, R4 or a strict bare run; a command's own time; a window's start, also when the window extends a manual countdown (S1), which makes the fill full again; the kept beginning, `_kept_beginning(at)` = `min(kept, at)` for the instant the writer works at, for adding, subtracting and S2 realignment (a bare run of a running target writes nothing); null otherwise; a v3 file migrates to null and its countdown shows a full fill; a beginning at or after the end, or without an end, is a corrupt file** — the fill must be right after a late fold or a restart (P3, §5.7); a clock that steps back must never make the stored file unreadable; an upgrade must not invent a beginning — a countdown running during the upgrade has no progress until it is set again; a window over a manual countdown restarts the fill.
6. **The fill is the share of the countdown that is left (full at the start, empty at the end), clamped to 0..1; time left is `M:SS`/`H:MM:SS` rounded up, like the Run for number (§6.1); Home Assistant's timer card floors** — matches C4's "open run full, idle empty", agrees with the number on the device page, and is plural-free in every language — none.
7. **Card strings are typed by the keys of `en.json` `common`; that English is bundled and used only before any card has loaded strings; config errors, the picker entry and the editor's labels use `lastLoaded()`, the last `hass` whose strings arrived; everything else uses the card's own `hass.localize` after `loadBackendTranslation("common", "timerify")`** — a misspelt key fails `tsc`; `setConfig` and `getConfigForm` run without `hass` — the English text is built into the bundle, rebuilt with every change of `en.json` (`build:check` catches a stale one); a page whose first card is invalid shows that error in English.
8. **`timerify/timer` answers any Timerify timer entry whatever its state (C3 as amended); the lookup is asked again on a new configured entity, a new `hass.entities`, `hass.connected` turning true and the number's state becoming available; a `not_found` warns only while the number is missing or has a value, never while it is `unavailable`; any other failure shows the card as unavailable until the next trigger** — the answer is configuration, so a lookup that meets an entry still starting (every start and every reload) is answered — none.
9. **Presets default to 15, 30, 45, 60 and 120 minutes and accept digit strings (the editor's `select` writes strings); a new card from the picker carries them, so the editor shows them; ± steps 5 minutes and is not configurable; `−` is offered only while counting; the chip is ignored by the round layout** — the owner's 45 minutes and the common lengths; a user who adds one preset must not lose the others unseen; C9 lists no step field — a user who wants another step uses a preset.
10. **A tap is the `click` event (mouse, touch, keyboard, assistive technology); a hold is added on top: it fires on release after at least 500 ms, as Home Assistant's own handler, and swallows the click that follows; a cancelled or moved-off pointer aborts; the chip is a sibling of the body, so its presses never reach it; the context menu is suppressed while a hold is pending; the body has `user-select: none; -webkit-touch-callout: none`; the pill has no hold — with a mouse a long press there is a tap, on touch it does nothing; `data-held` marks a hold in progress (the ring pulses)** — one event path, so a hold never also opens the pop-up and the chip never does — keyboard users start and stop through the pop-up.
11. **The pop-up closes on Escape, on its close button and on a click whose target is the dialog itself (the backdrop; the dialog has no padding of its own); the browser's Back is not intercepted (Chromium on Android closes a modal dialog by itself, unverified in the companion apps); a refused action is reported by Home Assistant's own toast (`notifyOnError`, a top-layer popover above the dialog), and the card catches the rejection and stays open** — no history handling that HA's internals own — Back on iOS leaves the view.
12. **`ha-card`, `ha-icon` (`.icon`) and `ha-state-icon` (`.stateObj` only) are the only frontend elements rendered; nothing waits for their definition; `ha-state-icon` reads formatters and entities from the frontend's Lit contexts, so outside `<home-assistant>` (vitest) it shows no icon, which is expected** — the icon logic of every domain and the theme's card frame exist nowhere else; they are defined when a card connects (research §1) — if one is renamed, the card loses its frame or icon, not its function.
13. **Clock times: the same local day shows the time, the next six days the short weekday and time, later ones the date and time; they honour `locale.time_zone` ("server" is `hass.config.time_zone`) and `time_format` (`12`, `24`, `system` = the browser's locale, `language` = the user's language); minutes are whole, so `number_format` changes nothing but grouping, which is off** — a timer ends at most a day ahead and a command at most seven — none.
14. **A new `hass` renders the card only when one of its own entities' state objects, the locale, the language, `localize`, `config`, the user, the connection or the registry changed; any update that does not carry a new `hass` passes; the pop-up renders its content only while open and applies the same filter, and gets a fresh `view` from each card render so its time ticks** — the setter runs on every state change of the home (research §2); strings arrive as a new `localize` alone — none.
15. **The E2E harness is `scripts/harness/hass.py` (moved from the smoke script, parameterised by project, port and config directory), driven for the E2E by `python -m scripts.e2e.hass up|restart|down`, which Playwright's global setup and teardown call from the repository root; the smoke test now runs as `uv run python -m scripts.smoke.run`** — one onboarding and compose path; smoke (18123) and E2E (18124) can run side by side — the smoke command changes.
16. **E2E runs serially against one container at `http://localhost:18124` in New York time; before each test the fixture is restored whole (numbers 0, commands cancelled and the fixture command added again, the interval switch on; the interval sits 12 hours from the run), and each test creates its own starting point; tests get 60 s and assertions 10 s, the restart test 300 s and 120 s for the countdown to return; users act with long-lived tokens written by `up`; a Russian test uses a context with `locale: "ru-RU"`; the non-admin is a `system-users` user made over the websocket API** — the container runs on the real clock and a restart takes tens of seconds; the frontend picks the browser language for a user who chose none — a failing run is slower to report.
17. **Screenshots are taken by a separate Playwright project (`npm --prefix card run screenshots`) with the browser clock fixed at `started_at` + 15 minutes, and committed in Task 9, not by every E2E run (an amendment of C11, confirmed by the controller)** — a countdown changes every second, so the gate would leave a dirty tree; the fixed clock fixes the time left and the fill, while the end time shown is the server's real one, so a rerun changes the images; they are refreshed by hand when the look changes (amended after the Task 5 review: no server data is faked for a picture).
